For a DE store/portal built on Replit, you should have Replit implement the **baseline modern web security set**, plus **e-commerce + form defenses**, and **admin hardening**. Below is the exact checklist to give them.

## Must-have (non-negotiable)

### Transport + headers

* **HTTPS everywhere + HSTS**
* Secure headers:

  * **CSP** (at least a solid baseline)
  * **frame-ancestors** (clickjacking protection)
  * **X-Content-Type-Options: nosniff**
  * **Referrer-Policy**
  * **Permissions-Policy** (basic lockdown)

### Identity + sessions

* **SSO/OIDC** (Microsoft/Google) *or* email + MFA (but SSO is better for DE clients)
* **MFA required for admins**
* Sessions via **secure cookies**: `HttpOnly`, `Secure`, `SameSite=Lax/Strict`
* **Session rotation** after login + privilege changes
* **Re-auth (step-up)** for sensitive actions (billing, admin, exporting data)

### Access control

* **RBAC** roles:

  * Public (anonymous)
  * Prospect (unverified)
  * Client (Managed)
  * Client (Co-Managed)
  * Admin (DE)
* **Permission checks server-side** on every protected route/API
* Separate **admin area** (different paths + stricter rules)

### Web app + API protections

* **Server-side input validation** (schema validation on every form/API)
* **CSRF protection** for cookie-based sessions
* **Rate limiting** (by IP + by account) on:

  * login, password reset
  * contact/quote forms
  * checkout / cart actions
  * API endpoints
* **SQL/NoSQL injection prevention** (parameterized queries / safe ORM)
* **XSS defenses** (escaping + sanitizer for any rich text + CSP)
* **File upload security** (if you allow uploads):

  * allowlist file types
  * size limits
  * malware scan
  * store outside webroot using signed URLs

### Bot / spam protection (forms)

* **Cloudflare Turnstile** (or hCaptcha) on:

  * lead forms
  * account creation
  * password reset
* **Honeypot field** + submission timing checks
* **Email verification** for new accounts

### Logging + audit

* **Audit trail** for:

  * admin changes
  * pricing/product changes
  * client account changes
  * checkout actions (orders, refunds)
* Centralized logs + alerting for:

  * repeated failed logins
  * rate-limit triggers
  * admin role changes
  * suspicious checkout patterns

---

## If you support checkout (recommended approach)

### Payments

* Use a **hosted PCI provider** (Stripe Checkout / similar)
* **Do not store card data** (tokenization only)
* Enable:

  * **3DS/SCA** where applicable
  * fraud checks (built-in provider scoring)
* Order confirmation webhooks must be:

  * **signed** and verified
  * idempotent (safe to replay)

---

## Strongly recommended (high value)

### Edge protection

* Put the site behind a **CDN/WAF** (Cloudflare is easiest)
* **DDoS protection** (usually included with CDN)
* Basic **bot management** (block obvious automation)

### Secrets + deployment hygiene

* Secrets stored in a **secrets manager** (not in code)
* **Secret scanning** in repo + CI
* Dependency scanning (SCA)

### Account takeover defense

* Password policy + **breached password checks**
* Login anomaly detection (new geo/device) if feasible

---

## Optional (only if needed)

* **Passkeys/WebAuthn** for clients (nice-to-have)
* **mTLS** for admin portal (overkill unless very sensitive)
* **Field-level encryption** for special PII (usually not needed for your store)

# DE-specific rules to implement (matches your model)

### Managed Clients

* Can log in and view catalog, but:

  * **Managed/Security services are non-purchasable**
  * CTA = **Schedule Consultant / Request Quote**
  * These actions create a lead + booking + internal task

### Co-Managed Clients

* Checkout-enabled SKUs:

  * Co-managed subscriptions
  * Networking solutions
  * UCaaS
  * Hardware + mandatory provisioning
  * Digital products

This requires **catalog segmentation** + RBAC gating.
