Co-Managed Solutions: the “thoughts we need” (DE Service Provider Mode)
Core principle

Co-Managed = DE delivers a defined outcome inside a defined boundary.
Anything outside the boundary remains owned by the client’s internal IT, their MSP, or their helpdesk.

This lets DE support:

Cyber only

Network only

Projects / vendor support only

Hardware procurement + implementation (dropship + installer)
…without DE inheriting full-environment risk.

1) The 3 Co-Managed engagement modes (your structure)
A) Outcome Co-Managed (Cyber Only / Network Only / Identity Only)

Use when: the client wants DE for one pillar, while keeping their existing IT team or MSP for everything else.

DE owns

Configuration, monitoring, tuning, and reporting for the systems in scope

Defined response actions inside the scope (e.g., containment actions you’re authorized to perform)

Client/Other provider owns

Everything else (endpoints not enrolled, network gear not managed, unsupported apps, user training not included, etc.)

Root-cause remediation that requires systems outside scope

Result: “DE provides the capability; the client/other IT owns the environment.”

B) Pre-Provisioned IT Assets (Dropship + Implement)

Use when: you want repeatable deployments with predictable margin and fast time-to-value.

DE provides

Approved standardized SKUs (endpoints, phones, network gear, accessories)

Pre-provisioning (policies, enrollment, templates, baseline hardening)

Shipping direct to client site

Implementation options (below)

Implementation paths

DE-Coordinated Field Installation (FieldNation / partner tech)

Client Self-Install (guided steps + remote validation)

Hybrid (client installs, DE validates + finishes remotely)

Result: scalable delivery without needing full MSP takeover.

C) Co-Managed With Other Companies (Permissioned Service)

Use when: there is another MSP/vendor/IT department and you are working “inside their ecosystem.”

Two variations:

Service Someone Else’s Stack (permissioned)

You support systems owned/managed by another provider only with written permission + defined access + training alignment.

Vendor Support + White-Glove (non-managed clients)

You provide vendor escalation, deployment assistance, and “white glove” outcomes

The business is not a ProActive Ecosystem client

Scope is narrow, ticket types are limited, and response obligations are limited

Result: DE is a specialist layer, not the primary risk-holder.

2) The Risk Rule (how you explain it cleanly)
ProActive Ecosystem = only way DE accepts broad responsibility

DE takes on operational/security risk only when the client is on a DE ProActive Ecosystem bundle.
That is the model that includes:

full minimum standards,

ongoing lifecycle management,

baseline controls,

and the ability to enforce remediation.

Co-Managed = limited-scope responsibility only

If a client uses DE for Security only or Network only while keeping internal IT/MSP/helpdesk:

They own the overall outcomes of the environment.

DE is accountable only to the contracted scope (the tasks, systems, and deliverables you were hired to perform).

The “decline/waiver” logic (keep this consistent)

In ProActive Ecosystem, the client can decline recommendations, but that decision limits DE’s responsibility related to that declined area.

In Co-Managed, the boundary is narrower from the start: DE is never the “overall owner,” only the “scope owner.”

3) How to package “one-to-a-few offerings per client” (menu approach)
Offer Category 1: Cyber Only (Co-Managed Cyber)

Good when the client has IT staff but wants security outcomes.

Typical scope blocks

Email security / anti-phishing controls

Endpoint security + EDR

Identity security (SSO/MFA/conditional access)

Security monitoring + alert handling for enrolled assets

Vulnerability posture reporting + remediation guidance (not full remediation unless contracted)

Deliverables

Monthly security posture report

Incident/alert summary

Action plan (what DE recommends, what client/other IT executes)

Offer Category 2: Network Only (Co-Managed Network)

Good when the client’s security is “okay” but their network is aging or unmanaged.

Typical scope blocks

Router/firewall/Wi-Fi/switch management for supported models

Monitoring + firmware lifecycle tracking

Upgrade timeline planning (EOL tracking + replacement plan)

Remote support and vendor escalation (in-scope gear only)

Deliverables

Network health report

EOL/refresh roadmap

Configuration standards + change log

Offer Category 3: Pre-Provisioned Assets + Implementation

Good when you want to productize delivery.

Scope blocks

Standardized device bundles (endpoint/phone/network)

Provisioning templates + baseline hardening

Dropship logistics + asset tracking

Install option selection (FieldNation / DIY / Hybrid)

Deliverables

Bill of materials + config profile summary

Install completion validation

Acceptance checklist signed off

Offer Category 4: Vendor Support + White-Glove (Non-Managed)

Good when you want revenue from non-Ecosystem clients without taking broad risk.

Scope blocks

“We interface with vendor support on your behalf”

“We implement and validate a defined change”

“We provide remote white glove assistance for a fixed list of tasks”

Deliverables

Case notes, outcomes, and next steps

Clear exclusions + handoff back to their IT

4) Boundaries you’ll want stated everywhere (simple, repeatable rules)
Scope boundaries (non-negotiable)

Only enrolled/managed assets are supported.

Only approved hardware models are supported (or “best effort” is billed differently).

DE does not become the default helpdesk unless contracted.

DE does not own remediation outside scope (but can provide guidance or a separate SOW).

Access and permission boundaries

If DE is supporting another provider’s environment:

written permission,

defined admin roles,

change approval rules,

escalation paths,

and training alignment.

Outcome boundaries

Co-Managed = DE delivers its part; overall environment ownership remains with the client/other IT.

5) The clean way to describe this in client language (paste-ready)

Co-Managed Solutions
DE can be engaged as a specialized provider for Cyber Only, Network Only, or Pre-Provisioned IT Assets without requiring a full managed-services transition. In co-managed engagements, DE is responsible only for the systems and deliverables defined in the scope of work, while your internal IT team (or existing provider) retains ownership of the broader environment, day-to-day operations, and any remediation outside the agreed scope.

Risk & Responsibility
DE’s ProActive Ecosystem bundles are the only engagement model where DE accepts broad operational and security responsibility across the client environment. Co-managed engagements are intentionally limited in scope, allowing the client to retain control and responsibility for all areas not explicitly covered.

6) Quick internal decision rule (so you stay consistent)

If the client wants DE to be accountable for security outcomes across the business, push them to ProActive Ecosystem.
If the client wants DE for one pillar, keep it Co-Managed with tight boundaries and explicit exclusions.
