Issues to fix before “client-facing” use ⚠️
1) Placeholder styles are inconsistent (this will break automation)

Your templates currently mix multiple placeholder formats:

«Field Name» (appears in 9 DOCX/PDFs, including MSA + Order Form + many SOWs)

[FILL - ...] / [FILL] (appears in 3 documents)

Plain signature lines / blanks in others

Docs using [FILL …]:

NDA-Mutual-Confidentiality-Agreement...

SOW-CSRA-Ultimate-Cybersecurity-Risk-Assessment...

SOW-Invoice-Terms-and-Conditions...

If Replit is generating PDFs dynamically, you want one token format everywhere (recommended: {{snake_case}}), otherwise your “fill + generate + sign” pipeline becomes brittle.

2) Several PDFs still include visible placeholders

Some PDFs currently show «…» or FILL text. That’s fine if you treat PDFs as template exports only, but it’s not acceptable for clients as-is.

3) One filename contains two versions

SOW-DE-Managed-Assessments-2026-v2026.5-v2026.6.(docx/pdf)

This should be normalized to v2026.6 (after confirming header/footer inside the doc is truly 2026.6).

Recommended “Replit-ready” structure (so the app can curate packets reliably)
A) Treat DOCX as the source of truth

Store DOCX templates in the repo

Generate final PDFs at runtime after populating placeholders

Only keep static PDFs for internal preview unless they are guaranteed clean

B) Create a “document manifest” as the system’s source of truth

Your app should not rely on filenames alone. Use a manifest.json that defines:

document id

version

order (serve sequence)

depends_on (ex: SOWs depend on MSA)

requires_signature

selection_key (maps to the Order Form web selection)

This is what allows: “client chose X + Y → system assembles packet Z.”

C) Decide what the Order Form web page must collect

At minimum, your “registration/order flow” should collect everything needed to populate templates:

Client legal name, address, signatory name/title/email

Effective date, billing start date, term

Service selections + quantities + pricing

Any SOW-specific configuration fields (or move them to a separate onboarding questionnaire)
